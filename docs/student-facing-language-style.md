# Student-facing language style

## Purpose

This guide controls the language in the interactive course and the lecture notes.
It supplements the technical and source-fidelity rules in \`AGENTS.md\`.

The reader is a second-year engineering student. English can be the reader's second language.

## Source and teaching order

- Keep the order, notation, examples, and warnings from the lecture notes.
- Use the slides as the model for short headings and direct presentation.
- Use the textbook only to verify a detail or fill a documented gap.
- Explain an idea in plain words before its mathematics.
- Name the common student error after the method or result.

## Headings

- Use a technical topic, definition, result, model limit, or common error as the heading.
- Prefer \`Sampling theorem\`, \`Model limit\`, and \`Common error\`.
- Do not use promotional, conversational, or suspense-based headings.
- Avoid headings such as \`Why this matters\`, \`What this really means\`, and \`The rule worth remembering\`.
- Use a question only when the source uses it to introduce a necessary problem.

## Sentences and paragraphs

- Keep a descriptive sentence at 25 words or fewer when the mathematics permits it.
- Keep an instruction at 20 words or fewer.
- Put one new fact in each sentence.
- Put one main idea in each paragraph.
- Use common words, active voice, and direct grammar.
- Define a technical term when it first appears.
- Use one name for each technical concept throughout the course.
- Remove idioms, metaphors, sales language, filler, and decorative transitions.
- Keep equations separate from long prose.

## Scene structure

A standard teaching scene uses this order:

1. A neutral technical title.
2. One short statement of purpose.
3. The definition, figure, or equation.
4. One short interpretation.
5. One common error or model limit, when needed.

Worked examples keep the \`Given\`, \`Find\`, \`Method\`, \`Solution\`, and \`Check\` structure.

## Protected content

Do not change these items during a language pass:

- equations, notation, numerical results, or technical assumptions;
- scene identifiers, reveal order, navigation, or interactions;
- laboratory behavior or question counts;
- source anchors or the meaning of a worked example.

Split a scene only when the shorter language still does not fit at a scale of 0.90 or more.

## Review

For each changed section:

1. Compare the teaching order and technical claims with the lecture notes.
2. Compare the heading style and text density with the slides.
3. Count the longest sentences and split those that exceed the limits.
4. Build the interactive course and the lecture notes.
5. Run the project gates and inspect the rendered output.
